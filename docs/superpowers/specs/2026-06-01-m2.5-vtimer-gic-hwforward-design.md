# Hypervisor — M2.5 (Physical Timer + GIC + HW-Forwarding) Design

- **Date**: 2026-06-01
- **Project**: `hypervisor-`
- **Milestone**: M2.5 — Physical timer + GIC + hardware-forwarded injection
- **Target platform**: QEMU `virt` (AArch64), GICv3, Cortex-A72
- **Status**: Design approved, ready for implementation planning

> Split out of the original combined M2 spec (now superseded). M2.5 drives the vGIC
> delivery path — **proven in isolation by M2** — from a *real* hardware interrupt:
> the EL1 virtual timer, routed through the physical GICv3 and forwarded to the guest
> with `ICH_LR.HW=1`. **ADR-0001 (`docs/adr/0001-vtimer-hardware-forwarding.md`)
> belongs to this milestone.**

---

## 1. Purpose & Positioning

M2 proved the hypervisor can present a *software-injected* virtual interrupt to the
guest. M2.5 replaces the HVC trigger with a genuine physical interrupt: it
initialises the physical GICv3, configures the EL1 virtual timer, takes the timer
PPI at EL2, and **hardware-forwards** it into the guest's vGIC. The result is the
classic end-to-end timer-interrupt chain.

This is the hardware-heavy half of the original M2, deliberately deferred so that the
physical GIC, the new EL2 IRQ exception path, and the level-triggered re-pend storm
fix all land *after* the virtual delivery mechanism is already known-good.

### Roadmap context

| Milestone | Goal |
|---|---|
| M2 — vGIC software injection *(done before this)* | HVC → `vgic_inject_sw` → guest EL1 handler |
| **M2.5 — Physical timer + GIC + HW-forwarding** *(this spec)* | timer PPI → EL2 → `vgic_inject_hw` → guest |
| M3 — Linux Guest | distributor MMIO emulation, many INTIDs, SMP |

## 2. Scope

### 2.1 In scope (M2.5)

- **Physical GICv3 init** (`gic_init`): `GICD_CTLR` affinity routing + Group 1 NS;
  CPU0 redistributor wake; PPI 27 Group 1 NS, priority `0xA0`, enabled;
  `ICC_SRE_EL2.Enable=1`; EL2 `ICC_PMR_EL1`/`ICC_IGRPEN1_EL1`; **`ICC_CTLR_EL1.EOImode
  =1`** (split priority-drop / deactivate).
- **EL2 IRQ entry**: vector slot `+0x480` wired to `el1_irq_handler_asm` (saves guest
  state, calls `el2_irq_handler`, restores, `daifclr #2`, `eret`).
- **EL2 `DAIF.I` unmasking** on the `vcpu_run` guest-entry `eret` and the IRQ-return
  `eret`, so physical IRQs are actually taken at EL2.
- **Virtual timer**: `CNTHCTL_EL2=0b11`, `CNTVOFF_EL2=0`.
- **Hardware-forwarded injection**: `vgic_inject_hw(vcpu, vintid, pintid, prio)` —
  `ICH_LR0` with `HW=1` (bit 61) and the physical INTID in pINTID `[44:32]`.
- **`el2_irq_handler`**: `gic_ack_irq` → `vgic_inject_hw(27,27,0xA0)` →
  `gic_priority_drop` only (no deactivate); unexpected INTIDs are priority-dropped
  *and* deactivated.
- **M2.5 timer test payload**: the guest arms `CNTV_*`, waits, handles the forwarded
  vIRQ, deactivates it (releasing the physical INTID via the HW linkage), HVCs done.

### 2.2 Out of scope

- Multiple vCPUs / SMP / PSCI `CPU_ON` (M3).
- Full `GICD_*`/`GICR_*` MMIO trap-and-emulate (M3, for an unmodified Linux guest).
- Multiple SPIs/SGIs/MSI-LPI; multi-LR allocation across `ICH_LR0..LRn` (M3).
- `CNTVOFF` virtualization / per-VM timebase.
- FP/SIMD save/restore.

## 3. Architecture

### 3.1 End-to-end flow

```
main.c
  gic_init()                       ← GICD, GICR CPU0, ICC_SRE_EL2, EOImode=1, PPI 27
  vtimer_init()                    ← CNTHCTL_EL2=3, CNTVOFF_EL2=0
  vm_init() / vm_run() / vcpu_run(...)
    │   msr daifclr, #2            ← NEW vs M2: unmask IRQ at EL2 (HCR_EL2.IMO routes here)
    │   eret ──────────────────────────────────────► EL1 SVM
    │                                                  │ arm CNTV_TVAL/CTL ; daifclr#2 ; wfi
    │                                                  ▼ [timer PPI fires, level-asserted]
    │◄── el1_irq_handler_asm (+0x480) ──────────────────┘  (physical IRQ via IMO=1)
    │   save guest state
    │   el2_irq_handler():
    │       intid = gic_ack_irq()                 # ICC_IAR1 → phys 27 now Active
    │       vgic_inject_hw(vcpu, 27, 27, 0xA0)    # HW=1 forwarded
    │       gic_priority_drop(intid)              # EOIR1 only; do NOT deactivate
    │   restore guest state ; msr daifclr,#2 ; eret ─► EL1 SVM
    │                                                  │ vGIC delivers vIRQ
    │                                                  ▼ svm IRQ handler: IAR1 → disarm CNTV
    │                                                  │ EOIR1/DIR (releases phys 27 via HW link)
    │                                                  │ hvc HC_GUEST_DONE
    │◄── el1_sync_handler (+0x400) ─────────────────────┘ → hv_restore → back to main.c
```

### 3.2 HCR_EL2 / DAIF

`HCR_EL2` is unchanged from M1 (`VM|FMO|IMO|AMO|RW`); `IMO=1` is what routes the
physical IRQ to EL2. The change vs M2 is **DAIF.I**: M2 never unmasked it (no physical
IRQ existed); M2.5 unmasks it on the guest-entry and IRQ-return `eret` paths. EL2 is
never left running with IRQs unmasked outside a guest window (auto-masked on every
exception entry).

## 4. Component Design

### 4.1 Physical GICv3 (`gic_v3.c`)

Bases in `board.h`: `GICD=0x08000000`, `GICR CPU0=0x080A0000`, `BOARD_VTIMER_IRQ=27`.
`gic_init()`: enable `GICD_CTLR` (ARE_NS|ENGRP1NS); wake CPU0 RD; PPI 27 → Group 1
NS, prio `0xA0`, enabled; `ICC_SRE_EL2=0xF`; `ICC_PMR_EL1=0xFF`,
`ICC_IGRPEN1_EL1=1`, `ICC_CTLR_EL1.EOImode=1`. API: `gic_ack_irq` (`ICC_IAR1_EL1`,
24-bit), `gic_priority_drop` (`ICC_EOIR1_EL1`), `gic_deactivate` (`ICC_DIR_EL1`).
Setting EL2 physical `EOImode` does not affect the guest's virtual interface
(governed by `ICH_VMCR_EL2.VEOIM`).

### 4.2 HW-forwarded injection (`vgic_inject_hw`)

Adds to M2's vGIC: `ICH_LR0 = Pending | HW(bit61) | Group1 | prio<<48 | pintid<<32 |
vintid`. No `isb` (the eret synchronises).

### 4.3 EL2 IRQ entry (`irq_handler_asm.S` + `irq_handler.c`)

`el1_irq_handler_asm` mirrors `el1_sync_handler`'s save/restore against
`g_vm.vcpu.regs`, ending with `msr daifclr, #2` before `eret`. `el2_irq_handler`
forwards INTID 27 (see §3.1) and leaves it **Active** to avoid the storm (§5.1).

### 4.4 Virtual timer (`vtimer.c`)

`CNTHCTL_EL2=0b11` (guest may read `CNTPCT_EL0` / access physical timer regs without
trapping as `EC=0x18`); `CNTVOFF_EL2=0`. Must be called before `vm_run()`.

## 5. Design Decisions

### 5.1 HW-forwarded timer injection (ADR-0001)

**Decision:** forward the timer PPI with `ICH_LR.HW=1`; EL2 priority-drops only and
leaves the physical INTID **Active**; the guest's deactivate of the *virtual*
interrupt releases the physical one via the LR linkage. Requires
`ICC_CTLR_EL1.EOImode=1`. **Rejected:** software injection + EL2 deactivate — the
level-triggered timer line re-pends immediately and, being routed to EL2, storms the
guest before it runs. **Full rationale and alternatives:**
`docs/adr/0001-vtimer-hardware-forwarding.md`. **Revisit:** M3 (many INTIDs, multi-LR
allocation).

### 5.2 Hypervisor-owned physical GIC

The hypervisor owns the physical GIC; the guest gets only the `ICC_*` interface.
Foundational type-1 policy (see the combined-spec history / ADR if formalised later).

### 5.3 `CNTVOFF_EL2 = 0`; hard-coded GIC bases & PPI 27

Single VM, no migration → no virtual offset needed. GIC bases / INTID 27 are fixed
board constants (board-header convention); a DT/ACPI discovery path is an M4 concern.

## 6. Acceptance Criteria

1. **Build**: zero warnings; new objects under `build/obj/arch/arm64/irq/` and
   `.../timer/`; entry `0x40080000`.
2. **Functional** (`tests/run_svm2_test.sh`): the ten ordered lines —

   ```
   [hv] GIC: initialized (dist=0x8000000 rdist=0x80a0000 PPI=27)
   [hv] vtimer: CNTHCTL_EL2=0x3, CNTVOFF_EL2=0x0
   [hv] SVM: launching VMID=1 entry=0x40200000
   [svm] EL1 init
   [svm] GIC EL1 configured
   [svm] virtual timer armed
   [svm] virtual timer IRQ received (INTID=27)
   [svm] signalling HVC done
   [hv] SVM HVC: done (x1=0x0)
   ```

   (Plus the banner + `[hv] Hello from EL2` line.) The diagnostic line is `[svm]
   virtual timer IRQ received` — it proves physical-IRQ → EL2 → HW-forward → EL1
   delivery, with no re-pend storm.

## 7. Forward Compatibility (M3)

- `g_hv_ctx` / `g_vm` are single instances; SMP needs a per-physical-CPU "current
  vCPU" pointer (`TPIDR_EL2`) read at the top of every exception stub — the work is
  in the asm entry paths, not the C signatures.
- `el2_irq_handler` special-cases INTID 27; Linux needs an INTID→handler table,
  multi-LR allocation, and distributor MMIO emulation.
