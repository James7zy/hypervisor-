# M2.5 — Physical Timer + GIC + HW-Forwarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Context

M2 is complete and green: a guest HVC (`HC_INJECT_TEST`) software-injects a virtual IRQ that the guest's own EL1 handler receives (`make test-qemu-svm2` → `ALL PASS`). That proved the **vGIC delivery path** in isolation, with no physical hardware involved.

**M2.5 drives that same delivery path from a *real* hardware interrupt.** It initialises the physical GICv3, configures the EL1 virtual timer, takes the timer PPI (INTID 27) at EL2, and **hardware-forwards** it into the guest's vGIC (`ICH_LR0.HW=1`). The outcome is the classic end-to-end timer-interrupt chain: physical IRQ → EL2 → `vgic_inject_hw` → guest EL1 timer handler.

The design is already approved — this plan only translates it into the project's task-by-task, test-first house style.

- **Spec:** `docs/superpowers/specs/2026-06-01-m2.5-vtimer-gic-hwforward-design.md`
- **ADR-0001:** `docs/adr/0001-vtimer-hardware-forwarding.md` — *why* the timer PPI is forwarded with `HW=1` and EL2 priority-drops only (never deactivates): the timer line is level-sensitive, so an EL2 deactivate re-pends it instantly and — being EL2-routed (`HCR_EL2.IMO=1`) — storms the guest before it runs a single instruction. The fix requires `ICC_CTLR_EL1.EOImode=1` at EL2.

**Test-payload decision (made during planning):** the spec's acceptance names `tests/run_svm2_test.sh`, but `svm2` is now M2's live software-injection regression test (the spec predates that collision). This plan instead adds a **new `tests/svm3/` payload + `tests/run_svm3_test.sh`** for the timer scenario and **keeps `svm2` green as M2 regression** — matching the project's discipline of preserving every prior milestone's test.

## Architecture & flow (from spec §3.1)

```
hypervisor_main()
  gic_init()        ← GICD, GICR CPU0 wake, PPI 27 (Grp1 NS, prio 0xA0, enabled),
                      ICC_SRE_EL2=0xF, ICC_PMR_EL1=0xFF, ICC_IGRPEN1_EL1=1, EOImode=1
  vtimer_init()     ← CNTHCTL_EL2=0b11, CNTVOFF_EL2=0
  vm_init() / vm_run() / vcpu_run()
    │ msr daifclr,#2 ; eret ─────────────► EL1 svm3: arm CNTV_TVAL/CTL; daifclr#2; wfi
    │                                        ▼ [timer PPI fires, level-asserted, IMO→EL2]
    │◄ el1_irq_handler_asm (+0x480) ─────────┘
    │   save guest state
    │   el2_irq_handler():
    │     intid = gic_ack_irq()              # ICC_IAR1 → phys 27 now Active
    │     vgic_inject_hw(vcpu, 27, 27, 0xA0) # HW=1 forwarded
    │     gic_priority_drop(intid)           # EOIR1 only; NO deactivate
    │   restore guest state; msr daifclr,#2; eret ─► EL1 svm3
    │                                        │ vGIC delivers vIRQ → handler: IAR1; disarm CNTV
    │                                        │ EOIR1 + DIR (releases phys 27 via HW link)
    │                                        │ hvc HC_GUEST_DONE
    │◄ el1_sync_handler (+0x400) ────────────┘ → hv_restore → back to main.c
```

`HCR_EL2` is unchanged from M1 (`VM|FMO|IMO|AMO|RW`); `IMO=1` already routes the physical IRQ to EL2. The only PSTATE change vs M2 is unmasking **DAIF.I** on the two guest-facing `eret` paths.

## Key facts verified against the tree

- **Vector slot is free.** `hypervisor/arch/arm64/boot/vectors.S:25` — the Lower-EL-AArch64 IRQ slot (`+0x480`) is currently `VECTOR_ENTRY panic_vector`. M2.5 repoints it to `el1_irq_handler_asm`.
- **Save/restore template exists.** `el1_sync_handler` (`vmexit_asm.S:77-145`) saves guest x0–x30 + SP_EL1/ELR/SPSR against `g_vm.vcpu.regs` (which aliases `&g_vm`) and erets back. `el1_irq_handler_asm` mirrors it exactly, differing only in the C callee (`el2_irq_handler` vs `handle_exit`) and a trailing `msr daifclr,#2` before `eret`.
- **`vcpu_run` eret is at `vmexit_asm.S:71`** — add `msr daifclr,#2` immediately before it.
- **Boot masks all DAIF** at `head.S:47-50` (`msr daifset,#0xF`); EL2 re-masks I on every exception entry. We only ever unmask on the guest-entry / IRQ-return erets, so EL2 never runs with IRQs unmasked outside a guest window.
- **vGIC is in place.** `vgic.c/h` already has `vgic_init/inject_sw/restore/save` and the `ICH_LR_*` field macros (`ICH_LR_HW = 1<<61` already defined, `vgic.h:17`). M2.5 adds `vgic_inject_hw` beside `vgic_inject_sw`.
- **Sysreg accessor:** `asm/sysreg.h` `SYSREG_READ(reg)` / `SYSREG_WRITE(reg,val)` stringify the bare register name — used for all `ICC_*`/`ICH_*`/`CNT*` access.
- **`board.h` lacks GIC bases** (`qemu_virt/board.h` has UART/DRAM/SVM only). M2.5 adds `BOARD_GIC_DIST_BASE`, `BOARD_GIC_RDIST_BASE`, `BOARD_VTIMER_IRQ`.
- **QEMU machine** (`scripts/run-qemu.sh`) is already `-machine virt,virtualization=on,gic-version=3 -cpu cortex-a72 -smp 1`. GICv3 bases: `GICD=0x08000000`, `GICR CPU0 RD=0x080A0000` (SGI frame at `+0x10000` = `0x080B0000`).

- [ ] **Step 3 — `gic_v3.c` `gic_init()`** (MMIO via `volatile u32 *`, sysregs via `SYSREG_WRITE`):
  1. `GICD_CTLR` (`GICD+0x000`) = `ARE_NS(1<<4) | EnableGrp1NS(1<<1)`.
  2. Wake CPU0 redistributor: `GICR_WAKER` (`RD_base+0x014`) — clear `ProcessorSleep(1<<1)`, poll until `ChildrenAsleep(1<<2)==0`.
  3. PPI 27 in the SGI frame (`SGI_base = RD_base+0x10000`): `GICR_IGROUPR0(+0x080) |= 1<<27` (Group 1 NS); `GICR_IPRIORITYR` byte at `+0x400+27 = 0xA0`; `GICR_ISENABLER0(+0x100) = 1<<27` (enable).

  5. `printk("[hv] GIC: initialized (dist=0x%lx rdist=0x%lx PPI=%u)\n", BOARD_GIC_DIST_BASE, BOARD_GIC_RDIST_BASE, BOARD_VTIMER_IRQ);` — note printk has no width specifiers; the `0x8000000`/`0x80a0000` rendering matches `%lx` of the constants.
  6. `gic_ack_irq` = `SYSREG_READ(ICC_IAR1_EL1) & 0xFFFFFF`; `gic_priority_drop` = `SYSREG_WRITE(ICC_EOIR1_EL1, intid)`; `gic_deactivate` = `SYSREG_WRITE(ICC_DIR_EL1, intid)`.

  ```c
  /* Inject a pending, Group-1, hardware-forwarded (HW=1) virtual interrupt:
   * the physical INTID is linked in pINTID so the guest's deactivate of the
  ```
