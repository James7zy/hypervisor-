# M3.0 — Linux Alive (boot protocol + image launch + PL011 passthrough console) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boot an unmodified arm64 Linux `Image` far enough to print earlycon boot logs through a passed-through PL011, proving the arm64 boot protocol, guest-RAM Stage-2 mapping, and PSCI-over-HVC — then stall cleanly at the first GIC MMIO access (EC `0x24`), which is the M3.0 finish line handed to M3.1.

**Architecture:** The hypervisor stays at PA `0x40080000`. Guest RAM is a **dedicated PA region** (`0x48000000`, 256 MB) that does not overlap the hv image; Stage-2 maps guest IPA `0x40000000` → PA `0x48000000` (non-identity). QEMU `-device loader` drops the `Image` at PA `0x48080000` (= guest IPA `0x40080000`, arm64 `text_offset` 0x80000) and a hand-written `guest.dtb` at PA `0x4A000000` (= guest IPA `0x42000000`). The existing Stage-2 device block (`l1_table[0]`, IPA `0`–`0x3FFFFFFF` → PA identity, Device-nGnRE) **already covers the PL011 at `0x09000000`**, so PL011 passthrough needs no new mapping. The vCPU is launched per the arm64 Linux boot protocol (`x0 = dtb_ipa`, `x1=x2=x3=0`, `ELR_EL2 = 0x40080000`, `SPSR_EL2 = EL1h` DAIF-masked). vmexit is unchanged — the unbacked GICD read hits the existing `default` case and parks in `wfi`.

**Tech Stack:** C11 freestanding (`-ffreestanding -nostdlib -mgeneral-regs-only -mstrict-align -Werror`), aarch64 assembly, GNU Make, `dtc` (Device Tree Compiler), QEMU `qemu-system-aarch64` ≥ 6.0 with `-machine virt,gic-version=3`.

## Address Map (pinned)

These constants are referenced by every task. Define them once (Task 2) and reuse.

| Name | Guest IPA | Physical (PA) | Size | Notes |
|---|---|---|---|---|
| Guest RAM base | `0x40000000` | `0x48000000` | 256 MB | Non-identity. Upper half of QEMU `-m 1G` DRAM (`0x40000000`–`0x7FFFFFFF`). Hv image (~17 KB at `0x40080000`) is far below `0x48000000`. |
| Kernel `Image` | `0x40080000` | `0x48080000` | — | arm64 `text_offset` = `0x80000` from RAM base. |
| Guest DTB | `0x42000000` | `0x4A000000` | ≤ 32 MB headroom | 32 MB above RAM base; well clear of the kernel and its `.bss`/decompression scratch. |
| PL011 (passthrough) | `0x09000000` | `0x09000000` | 4 KB | Identity, Device-nGnRE — **already mapped** by the existing `l1_table[0]` device block. No new mapping. |
| GICD (intentional stall) | `0x08000000` | — | — | Unbacked in Stage-2 → data abort EC `0x24` → `wfi`. This is the DoD. |

PA→IPA offset for RAM is `0x08000000` (PA = IPA + `0x08000000` for the RAM region only). QEMU `-device loader,addr=` always takes **physical** addresses.

### Task 4: Make the Stage-2 guest-RAM block use a configurable PA (non-identity)

**Files:**
- Modify: `hypervisor/arch/arm64/mmu/stage2.h`
- Modify: `hypervisor/arch/arm64/mmu/stage2.c`

The current `stage2_init` hard-codes `l1_table[1] = 0x40000000 ...` (identity). We need guest IPA `0x40000000` → PA `0x48000000`. Both are inside the same 1 GB L1 entry index (`IPA >> 30 == 1`), so we keep one block per 1 GB and just point its output PA at `ram_pa`. The PL011 device block (`l1_table[0]`) is unchanged and still covers `0x09000000`.

```c

```

to:

```c

```

- [ ] **Step 2: Use `ram_pa` as the L1[1] output address in `stage2.c`**

In `stage2.c`, change the signature and the `l1_table[1]` line. Replace lines 35–46 (the whole `stage2_init` body) with:

```c
void stage2_init(struct vcpu *vcpu, u32 vmid, u64 ram_pa)
{
    /* IPA 0x00000000–0x3FFFFFFF → PA identity: Device (covers PL011 @ 0x09000000) */
    l1_table[0] = 0x00000000UL |
                  S2_BLOCK | S2_MEMATTR_DEV | S2_S2AP_RW | S2_SH_OSH | S2_AF | S2_XN;

    /*
     * IPA 0x40000000–0x7FFFFFFF → PA ram_pa: Normal WB (guest RAM).
     * Non-identity for the Linux guest: ram_pa is a dedicated region that
     * does not overlap the hv image at 0x40080000. The 1 GB block output
     * address must be 1 GB-aligned (low 30 bits zero); ram_pa is.
     */
    l1_table[1] = (ram_pa & 0xFFFFC0000000UL) |
                  S2_BLOCK | S2_MEMATTR_NORM | S2_S2AP_RW | S2_SH_ISH | S2_AF;

    vcpu->vttbr_el2 = ((u64)vmid << 48) | (u64)(uintptr_t)l1_table;
}
```

Note: the `0xFFFFC0000000` mask isolates PA bits [47:30] (1 GB-block output-address field for a 4 KB-granule L1 block). `BOARD_LINUX_RAM_PA = 0x48000000` is already 1 GB-aligned, so the mask is belt-and-suspenders.

### Task 5: Set the arm64 Linux boot-protocol register state in `vm_init`

**Files:**
- Modify: `hypervisor/common/vm/vm.c`

The arm64 Linux boot protocol requires at kernel entry: `x0` = physical (here IPA) address of the DTB, `x1=x2=x3=0`, the PC = kernel entry, executing in EL1h (the hv erets into EL1h) with all DAIF masked, MMU off, caches off, D-cache clean. The existing eret already lands in EL1h with DAIF masked via `SPSR_EL2 = 0x3C5`. We add the `x0..x3` setup and switch the active config to `linux_config`.

- [ ] **Step 1: Switch the active config to the Linux guest and set boot regs**

In `vm.c`, replace the body of `vm_init` (lines 12–38) with:

```c
void vm_init(void)
{
    g_vm.config = &linux_config;

    const struct vm_config *cfg = g_vm.config;

    /*
     * arm64 Linux boot protocol (Documentation/arm64/booting.rst):
     *   x0 = physical address of the DTB (here: guest IPA of the DTB)
     *   x1 = x2 = x3 = 0 (reserved, must be zero)
     *   PC = kernel entry; CPU in EL1h, DAIF masked, MMU/caches off.
     */
    g_vm.vcpu.regs.x[0] = (u64)cfg->dtb_ipa;
    g_vm.vcpu.regs.x[1] = 0;
    g_vm.vcpu.regs.x[2] = 0;
    g_vm.vcpu.regs.x[3] = 0;

    /*
     * SPSR_EL2 = 0x3C5: M[4:0]=00101 (EL1h, SP_EL1), DAIF=1111 (all masked).
     */
    g_vm.vcpu.regs.elr_el2  = cfg->entry;
    g_vm.vcpu.regs.spsr_el2 = 0x3C5ULL;
    g_vm.vcpu.regs.sp_el1   = cfg->mem_base + cfg->mem_size - 0x10UL;

    /*
     * HCR_EL2: VM(0)|FMO(3)|IMO(4)|AMO(5)|RW(31) set; HCD(29) clear (allow HVC).
     * RW=1: EL1 executes in AArch64 state.
     */
    g_vm.vcpu.hcr_el2 = (1ULL << 0) | (1ULL << 3) | (1ULL << 4) | (1ULL << 5) |
                        (1ULL << 31);

    stage2_init(&g_vm.vcpu, (u32)cfg->vmid, cfg->ram_pa);

    vgic_init(&g_vm.vcpu);

    printk("[hv] Linux guest: VMID=%u entry=0x%lx dtb=0x%lx ram_pa=0x%lx\n",
           (unsigned)cfg->vmid, (unsigned long)cfg->entry,
           (unsigned long)cfg->dtb_ipa, (unsigned long)cfg->ram_pa);
}
```

Note: `g_vm.vcpu.regs.x[0]` is set here, but `vcpu_run` (vmexit_asm.S) loads x0 last from `[vcpu+0x00]`, so the value survives into the guest. The existing register-load path needs no change.

### Task 6: Author the guest device tree (`guest/qemu_virt.dts`)

**Files:**
- Modify: `guest/qemu_virt.dts` (replace the Task-1 placeholder body)

The DTB must describe: 256 MB RAM at IPA `0x40000000`; one PSCI CPU; the PSCI node (HVC conduit, reusing the M1.5 responder); the arch timer (4 PPIs); the PL011 at `0x09000000`; a GICv3 node (present so the DT is complete — its MMIO is the intentional stall); and `/chosen` with earlycon bootargs. Interrupt numbers follow the QEMU `virt` / GICv3 conventions: PPI base 16, so vtimer (virt) PPI 11 → `<1 11 ...>`, and SPIs for PL011 IRQ 33 → `<0 1 ...>` (SPI 1).

- [ ] **Step 1: Replace `guest/qemu_virt.dts` with the full guest DT**

```dts
/dts-v1/;

/ {
    #address-cells = <2>;
    #size-cells = <2>;
    compatible = "linux,dummy-virt";
    model = "hv-guest-qemu-virt";
    interrupt-parent = <&gic>;

    chosen {
        /* PL011 is passed through at its physical base 0x09000000. */
        bootargs = "earlycon=pl011,0x9000000 console=ttyAMA0 nokaslr";
        stdout-path = "/pl011@9000000";
    };

    memory@40000000 {
        device_type = "memory";
        /* IPA base 0x40000000, size 0x10000000 (256 MB). */
        reg = <0x00000000 0x40000000 0x00000000 0x10000000>;
    };

    psci {
        compatible = "arm,psci-1.0", "arm,psci-0.2";
        method = "hvc";
    };

    cpus {
        #address-cells = <1>;
        #size-cells = <0>;

        cpu@0 {
            device_type = "cpu";
            compatible = "arm,cortex-a72";
            reg = <0x0>;
            enable-method = "psci";
        };
    };

    timer {
        compatible = "arm,armv8-timer";
        /*
         * GICv3 PPIs (interrupt-cells = <3>): type 1 = PPI, then PPI number,
         * then flags 0xf04 (level, all 4 CPU affinities). QEMU virt mapping:
         *   secure-phys 13, non-secure-phys 14, virt 11, hyp-phys 10.
         */
        interrupts = <1 13 0xf08>,
                     <1 14 0xf08>,
                     <1 11 0xf08>,
                     <1 10 0xf08>;
        always-on;
    };

    pl011: pl011@9000000 {
        compatible = "arm,pl011", "arm,primecell";
        reg = <0x00000000 0x09000000 0x00000000 0x00001000>;
        /* SPI 1 (GIC INTID 33). type 0 = SPI, num 1, flags 4 = level-high. */
        interrupts = <0 1 4>;
        clocks = <&apb_clk>, <&apb_clk>;
        clock-names = "uartclk", "apb_pclk";
    };

    apb_clk: apb-clk {
        compatible = "fixed-clock";
        #clock-cells = <0>;
        clock-frequency = <24000000>;
    };

    gic: interrupt-controller@8000000 {
        compatible = "arm,gic-v3";
        #interrupt-cells = <3>;
        #address-cells = <2>;
        #size-cells = <2>;
        ranges;
        interrupt-controller;
        /*
         * GICD @ 0x08000000 (64 KB), GICR @ 0x080A0000 (128 KB per QEMU virt).
         * These regions are UNBACKED in Stage-2 for M3.0: the first guest
         * access faults (EC 0x24) → hv default case → wfi. That stall is the
         * M3.0 finish line; M3.1/M3.2 back these with trap-and-emulate.
         */
        reg = <0x00000000 0x08000000 0x00000000 0x00010000>,
              <0x00000000 0x080a0000 0x00000000 0x00020000>;
    };
};
```

Replace the whole file with:

```sh
#!/bin/sh
set -eu

# M3.0: boot an unmodified arm64 Linux Image as the guest.
#   LINUX_IMAGE — path to a prebuilt arm64 'Image' (required)
#   GUEST_DTB   — path to the compiled guest DTB (default: build/guest/guest.dtb)
#
# Physical load addresses MUST match the hv address map (board.h):
#   Image @ 0x48080000  (guest IPA 0x40080000)
#   DTB   @ 0x4A000000  (guest IPA 0x42000000)
: "${LINUX_IMAGE:?LINUX_IMAGE must point to a prebuilt arm64 Image, e.g.: LINUX_IMAGE=/path/to/Image make run}"
GUEST_DTB="${GUEST_DTB:-build/guest/guest.dtb}"

[ -f "$GUEST_DTB" ] || { echo "ERROR: $GUEST_DTB not found. Run 'make guest' first."; exit 1; }

  -machine virt,virtualization=on,gic-version=3 \

  ${QEMU_EXTRA_ARGS:-}
```
