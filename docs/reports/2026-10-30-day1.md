## 架构师评审结论（关卡①）

**VERDICT: APPROVE_WITH_CHANGES**（方向/范围锁/ADR 兼容成立；编译 flag 集两个经实证
缺陷 + Makefile 集成一处遗漏，均为可执行修改，已全部修入 spec）。要点：

- **实证硬伤 ×2**（host gcc 13.3）：① `-O2` 无 `-fno-builtin` 时 memset 循环被优化
  成对自身的调用（无限递归，string_test 必挂死）；② Ubuntu 默认 `_FORTIFY_SOURCE`
  把被测 memset 重定向到 glibc `__memset_chk`（假绿）。→ flag 集钉死
  `-fno-builtin -U_FORTIFY_SOURCE`。
- **Makefile 集成遗漏**：`host-test` 必须进 Makefile:27 goal filter，否则解析期要求
  .config + 交叉工具链，普通 shell 跑不起来。
- **三项裁决**：host-test v1 不并入 `make test`（gate 语义不动），但进 loop 合并关卡②
  并落 CLAUDE.md 验证一节；输出纯文本不做机器格式；string_test 留作 flag 正确性哨兵。
- **TDD 措辞修正**：harness 自身无新实现可驱动，RED 证据=工作树内验收操作（故意错
  断言→观察 FAIL→还原），落库历史保持全绿；RED→GREEN commit 纪律从 M11 纯逻辑模块起适用。
- ADR 相容性：ADR-0009（其 Consequences 已预留此演进条件）、ADR-0015（与 x86
  link-check 同一逻辑）、ADR-0017 均无冲突；落地时给 ADR-0009 补修订记录。
